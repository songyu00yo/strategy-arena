# 模型接入与费用更新

2026 年 11 月 7 日补充：当前能力与启动方式以 [README](../README.md) 和 [内部质量门槛](quality-gate.md)为准。当前开发版已实现 5 种模型选择、目标补问、附件提取与快速复核，实现与真实验收分别记录。本轮已授权累计上限为 10 美元、650 次请求和 5,000,000 Token，环境限额须与中央账本审计值一致。以下 11 月 5 日及更早内容保留历史归属，不作为当前配置或验收状态。

## 当前实现与验收边界

2026 年 11 月 5 日，用户批准 DeepSeek、GPT 和自动三种模式。GPT 使用 OpenAI 官方 API 的 `gpt-6.1-terra`，推理档位为 `low`。同一条件版本的提案、质疑、修订、裁决和格式修复固定使用同一模型。

本分支已接入选择器、适配器和共享费用账本。当前验证使用 HTTP 测试替身和临时 SQLite，尚未用用户的 OpenAI Key 完成真实联调。3200 固定预览保持停止。历史 v0.2.0 及其 DeepSeek 记录保持原样。

## 选择规则

| 模式     | 行为                                                                     |
| -------- | ------------------------------------------------------------------------ |
| DeepSeek | 手动固定 DeepSeek，默认 `deepseek-flash`。                               |
| GPT      | 手动固定 `gpt-6.1-terra`。                                               |
| 自动     | 材料达到 6000 个字符，或明确限制达到 4 项时选 GPT；其他任务用 DeepSeek。 |

自动规则版本为 `cost-first-1.0.0`。材料去除首尾空格后按 Unicode 字符计数。限制按换行或中英文分号分隔，忽略空项；已填写的预算与时间各计一项。偏好不计入限制。规则不调用模型，也没有被验证为任务难度或模型质量的判断器。

表单显示当前选择与原因。缺少所选供应商的密钥时阻止提交，不因缺钥、限额或调用失败换供应商。重赛可以改模式；省略模式时继承上一版。自动模式在新条件下重新计算，旧版本保留当时的选择。

HTTP 创建请求沿用挑战字段，新增 `modelMode`。重赛请求为 `{ challenge, changeReason, modelMode? }`。模型选择独立于业务输入，不进入 Agent 的任务材料。每版本保存选择、原因、规则版本和配置指纹；其他供应商的配置变化不停止本轮。

## 本地配置

已有 `.env.local` 时保留原文件，参考 `.env.example` 补充配置。不要重新复制模板覆盖原有会话密钥和数据库设置。

- DeepSeek：`DEEPSEEK_API_KEY`，兼容旧 `MODEL_API_KEY`。旧 `MODEL_*` 参数只影响 DeepSeek。
- OpenAI：`OPENAI_API_KEY`。模型、价格、超时和输出上限使用独立 `OPENAI_*` 参数。
- 两家密钥只发往各自官方 HTTPS 接口。当前未开放第三方地址或任意 GPT 模型标识。
- 所有收费入口必须设置同一个绝对路径 `ARENA_BILLING_DATABASE_PATH`，例如本机 `data/billing.sqlite` 的完整路径。

只配置 Key 不代表 API 已连通。页面显示的是配置状态，实际可用性由真实响应确认。`node scripts/dev-local.mjs codex` 和 `claude` 会清空两家密钥及账本入口，只用于免费开发。

参考 [官方模型目录](https://developers.openai.com/api/docs/models) 和 [官方价目表](https://developers.openai.com/api/docs/pricing)，2026 年 11 月 5 日核对的 Terra 标准基础价为每百万输入 Token 1 美元、输出 Token 5 美元。代码按未缓存价格保守估算，不提前扣除缓存优惠。推理 Token 已包含在输出用量中，不重复相加。最终消费以服务商账单为准，账户权限与本聊天模型权限分别判断。

## 预算与账本

后续总授权为 200 美元。历史 DeepSeek 消费单独保留，新共享账本从后续请求开始记录。以下安排覆盖旧的后续人民币预算，不能把旧额度与新额度相加。

| 阶段               | 预算安排 |
| ------------------ | -------: |
| 适配与小样本联调   |  10 美元 |
| 冻结对照与问题复核 |  40 美元 |
| 试用与演示         |  70 美元 |
| 最终验收和评审预留 |  80 美元 |

当前初次启用默认累计上限为 **2 美元、100 次请求和 2,000,000 Token**，任何一项不足就停止。该上限覆盖所有工作区、网页、修复和命令调用，不是每局重置。开发上限最多 120 美元，代码不会自动动用最终 80 美元。

中央 SQLite 首次建立时固定金额、请求和 Token 上限。后续环境变量与记录不同会报错，避免另一工作区悄悄提高额度。阶段升额已有 `scripts/billing-admin.ts set-limits`，须有用户授权并保留审计记录；环境变量与审计后的累计限额必须一致。未知请求的双账本人工核销工具仍未提供，需要单独实现与验收。**不要删除账本、换新路径或手改 SQL 来恢复额度。**

费用以原币种的整数微单位保存，1 微单位为 0.000001 元或美元。页面的 `costCny`、`reservedCny` 与 `costUsd`、`reservedUsd` 分开显示。仅在总预算比较时，用固定的 6 元／美元折算人民币；这是保守的内部预算估算，不是实际汇率。

每次外部请求前，先原子预留最大输入、输出和费用，再发出请求。并发请求共用一个账本。已知用量按实际 Token 结算，格式失败也计入；缓存输入作为输入子集记录。重复尝试编号拒绝再次发送，修复使用新编号并重新预留。

超时、未知用量或入账失败保留预留，停止自动重试。进程在预留后崩溃，即使尚未发出请求，也保留这笔预留。已知实际用量超过估计时照实入账，并阻止后续超额请求。应用限额无法控制服务商额外计费或其他程序，因此仍需与官方账单核对。

新版本的应用账本与中央账本需要一起核销。旧 `reconcile-uncertain.ts` 会拒绝新版本请求，避免只释放其中一处。旧版人工核账流程继续适用于历史记录。

同机收费命令必须使用同一个账本绝对路径。部署到另一主机前，须停止原收费入口，备份并迁移账本；不得在两台主机各建一个 200 美元账本。本版没有跨主机费用同步。
