## 产品要解决的问题

方案擂台帮助用户比较学习、生活、工作或创作中的具体行动路线。用户填写目标、硬性限制、偏好和文字材料，系统用同一个模型形成 A、B、C 三条策略，再依次质疑、核验、修订和裁决。条件变化后另建版本，旧输入、证据、结果和费用保持可读。

A、B、C 是同一个模型的角色调用。三个角色不代表三个独立训练的模型。产品不能承诺结果正确、优于 GPT 或获得奖项。

## 代码导航与架构

浏览器通过同源 JSON 请求创建和推进擂台。服务端 runtime 先检查所有者、版本和费用，再认领一个步骤。模型适配器请求 DeepSeek，确定性工具核验材料或算术，结果写入 SQLite。SSE（Server-Sent Events，服务器发送事件）通知页面重新读取快照。

```text
表单与展示组件
  └─ use-arena.ts：请求、恢复、顺序推进、事件订阅
       └─ Next.js API：JSON 校验、来源检查、Cookie 身份
            └─ runtime.ts：步骤认领、配置指纹、预算、版本提交
                 ├─ model.ts + strict-schema.ts + prompts/protocol.ts
                 ├─ tools.ts：材料检索、受限算术、约束与关联校验
                 └─ db.ts + migrations/001_initial.sql：SQLite
```

## API 契约

所有 JSON POST 要求同源 `Origin` 和 `Content-Type: application/json`，请求体上限为 96 KiB。API 返回 `Cache-Control: no-store`。外部 HTTPS 预览必须设置正确的 `ARENA_PUBLIC_ORIGIN`；服务端不信任任意转发头。

### 请求与返回

| 方法与路径                           | 请求                                                                                                       | 成功返回                                                                                                            |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `GET /api/health`                    | 无。                                                                                                       | `200`：`status`、`version`、`commit`、`sourceDirty`、`model`、`requiresAccessCode` 和 `accessGranted`。不返回密钥。 |
| `POST /api/access`                   | `{ "code": "访问口令" }`，1～200 字符。                                                                    | `200`：`{ "accessGranted": true }`，写入访问 Cookie。                                                               |
| `POST /api/arenas`                   | `Challenge`，结构见下文。                                                                                  | `201`：完整 `ArenaSnapshot`，首次创建时写入所有者 Cookie。创建本身不调用模型。                                      |
| `GET /api/arenas/:id`                | 当前浏览器身份 Cookie。                                                                                    | `200`：完整 `ArenaSnapshot`。                                                                                       |
| `POST /api/arenas/:id/advance`       | `{ "versionId": "版本 UUID" }`。                                                                           | `200`：推进一个步骤后的快照；无可认领步骤时返回当前快照。此接口可能调用付费模型。                                   |
| `POST /api/arenas/:id/stop`          | `{ "versionId": "版本 UUID" }`。                                                                           | `200`：快照。停止后续步骤，已发出的请求仍归档。                                                                     |
| `POST /api/arenas/:id/versions`      | `{ "challenge": Challenge, "changeReason": "修改原因" }`，原因为 1～1,000 字符。                           | `200`：新版本快照，保留旧版。                                                                                       |
| `POST /api/arenas/:id/interventions` | `{ "targetStrategyId": "A", "targetClaimId": "实际主张 ID", "text": "用户质疑" }`，text 为 3～1,000 字符。 | `200`：附带用户质疑的新版本快照。                                                                                   |
| `GET /api/arenas/:id/events`         | `afterSeq` 查询参数或 `Last-Event-ID` 请求头。                                                             | SSE `event: arena`，data 为 `{ "events": [...] }`，id 为最新 seq。                                                  |

事件接口每秒检查一次记录，约 15 秒发送心跳，约 55 秒关闭连接。浏览器 EventSource 可重新连接。SSE 表示已有事件变化，不直接执行模型，也不表示整轮已经完成。

```json
  "timeHours": 8
}
```

| 字段                         | 约束                                                      |
| ---------------------------- | --------------------------------------------------------- |
| `goal`                       | 必填，8～3,000 字符。                                     |
| `constraints`、`preferences` | 默认空字符串，上限分别为 3,000 和 1,500 字符。            |
| `options`                    | 默认空数组，最多 3 项，每项 1～300 字符。                 |
| `materials`                  | 默认空字符串，最多 20,000 字符。                          |
| `domain`                     | `learning`、`life`、`work`、`creation` 或默认 `general`。 |
| `budget`                     | 默认 `null`，非空时为 0～100,000,000 的数字。             |
| `timeHours`                  | 默认 `null`，非空时为 0.01～100,000 的数字。              |

`ArenaSnapshot` 包含 `id`、`activeVersionId`、`createdAt`、`versions`、`steps`、`events` 和 `model`。每个版本保存输入、阶段、策略、质疑、证据、修订、裁决、费用、预留额、父版本、变更原因和配置指纹。费用字段为 `costCny` 与 `reservedCny`，界面应区分已记录估算与未结预留。

Strategy 的关键字段为 `id`、`title`、`thesis`、`steps`、`claims`、`resources`、`firstAction`、`failureCondition`、`estimatedCost` 和 `estimatedHours`。主张状态为 `user`、`estimate`、`unknown` 或 `supported`。Evidence 保留工具、结果、来源、算式、假设和关联攻击 ID。材料的 `sourceIds` 与 `Evidence.id` 用途不同，不应互换。

裁决 `outcome` 可为 `recommendation`、`tie`、`insufficient`、`infeasible` 或 `partial`。`preferred` 允许 `null`。不要为了让界面总有赢家而自行选择 A、B 或 C。工具失败、缺材料和不可行条件都应如实显示。

### 错误与身份

错误统一为 `{ "error": "可读说明", "code": "机器可读代码" }`。输入校验通常返回 `400 INVALID_REQUEST`；未知异常返回 `500 INTERNAL_ERROR`，保留已保存内容。

| HTTP / code                                           | 原因与处理                                                                       |
| ----------------------------------------------------- | -------------------------------------------------------------------------------- |
| `413 BODY_TOO_LARGE`、`415 INVALID_CONTENT_TYPE`      | 精简材料或使用 JSON 提交。                                                       |
| `403 INVALID_ORIGIN`                                  | 从正确站点重新操作；检查公开源配置，不绕过校验。                                 |
| `503 PUBLIC_ORIGIN_REQUIRED`、`INVALID_PUBLIC_ORIGIN` | 管理员修正源站配置。                                                             |
| `401 ACCESS_REQUIRED`、`INVALID_ACCESS_CODE`          | 输入有效预览口令。                                                               |
| `429 ACCESS_RATE_LIMIT`                               | 全局口令尝试达到每分钟 30 次，等待后再试。                                       |
| `503 ACCESS_NOT_CONFIGURED`、`SESSION_NOT_CONFIGURED` | 生产访问口令或至少 32 字符的会话密钥缺失。                                       |
| `404 NOT_FOUND`                                       | 擂台、版本不存在，或当前浏览器没有所有权。接口有意不泄露另一所有者的数据。       |
| `409 STALE_CLAIM`                                     | 用户质疑指向了旧主张，刷新当前版本再操作。                                       |
| `503 MODEL_NOT_CONFIGURED`                            | 无模型密钥；开发环境保持提示，不生成假回答。                                     |
| `429 DAILY_LIMIT`                                     | 当前身份当天创建次数达到限制；创建新版本也计数。默认每日 6 次，以 UTC 日期记账。 |
| `429 RUN_BUDGET`、`GLOBAL_BUDGET`                     | 本场及历史版本，或服务总费用和预留不足，不能继续请求。                           |
| `429 CONCURRENCY_LIMIT`                               | 运行中及未知模型请求占满并发，默认 3 个。先检查状态。                            |
| `503 INVALID_COST_CONFIG`                             | 费用估算配置无效，由管理员处理。                                                 |

模型步骤的格式、服务商或网络失败，也可能通过 `200` 快照返回，并把版本或步骤标为 `failed` 或 `uncertain`。页面须同时检查快照状态和 `error`，不能只用 HTTP 成功判断整轮成功。

所有者通过签名的 HttpOnly `arena_owner` Cookie 标识。访问口令 Cookie 为 `arena_access`。知道擂台 ID 不等于拥有权限。清除 Cookie、换浏览器或改会话密钥，可能失去历史访问；当前没有账号找回。不要把 localStorage 中的末次 ID 当作身份凭证。

## 状态、执行和费用保护

每版本计划 11 个常规步骤：3 次 propose、3 次 attack、1 次 verify、3 次 revise 和 1 次 judge。其中 10 次为常规模型调用，verify 执行本地工具。重复提案处理或一次格式修复可能增加调用，必须计入真实用量。

| 版本状态     | 含义与页面要求                                   |
| ------------ | ------------------------------------------------ |
| `ready`      | 等待下一步骤，可由页面或工作器推进。             |
| `running`    | 已认领步骤；展示真实进度，勿再建并行循环。       |
| `completed`  | 裁决步骤完成。仍须保留未知与局限。               |
| `paused`     | 用户停止，展示部分结论；已发出请求仍可能返回。   |
| `failed`     | 已知失败，展示原因和已有内容。                   |
| `uncertain`  | 请求是否完成或扣费未知，保留预留，停止自动重试。 |
| `superseded` | 条件变更替代了旧版本，取消尚未开始的步骤。       |

步骤另有 `pending`、`running`、`completed`、`failed`、`uncertain` 和 `skipped`。停止操作不会取消已到服务商的请求，也不保证退款。配置发生变化时，旧版本停止后续步骤；新建版本才能固定新配置。密钥轮换不进入配置指纹。

`use-arena.ts` 顺序推进，并用版本号和事件序号拒绝旧快照覆盖新状态。SSE 到达只触发刷新。页面与后台工作器共用认领机制。不要在展示组件增加第二个推进循环、盲目重试或伪造进度。

后台工作器默认关闭。`ARENA_WORKER_ENABLED=true` 只适用于长驻 Node.js 服务；进程关闭期间不会继续。多实例 SQLite 和 serverless 后台持续运行尚未验证。

## 模型配置、评测与预算

### 当前配置

默认配置来自 `config/model.json`：配置版本 `1.2.1`，提示词版本 `1.1.1`，Schema 版本 `1.0.0`。模型为 `deepseek-flash`，接口为 `https://api.deepseek.com/beta`，输出模式为 `strict-tool`，温度 `0.3`，单次输出上限 2,200 Token，超时 60,000 ms。

已知格式或引用错误，每步骤最多增加一次修复请求。原失败与用量保留，修复也受预算限制。超时、响应未完整收到或缺可信用量时，不自动重试，也不释放原预留。

| 现象                   | 先查什么                                                  | 恢复边界                                                                           |
