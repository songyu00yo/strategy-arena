# 需求澄清流程与验收

## 使用流程

在原首页输入目标并添加相关材料。A 拆解待决定事项，B 提供每轮 1～3 个具体问题。你提交回答后，系统根据答案继续细化。C 在候选交接和最终提交时查漏，有缺口就回到原补问区域。

“确认本轮回答并继续”确认本轮已填写答案。“确认要求并查漏交接”提交当前摘要并检查交接条件。自动保存保留草稿状态，未知、跳过和未填写内容继续未决。“先整理需求草稿”可以提前整理，结果列出剩余事项。

原三卡片分别显示 A、B、C 的实际结果。原完整结论展示需求说明、执行提示词、模型建议、未决事项和材料。新模式的报告文字保留换行，这项文字格式调整已获用户同意。原步骤详情可追溯角色、请求编号和用量。

修改已经确认的要求后，相关内容进入待确认。通过“我的历史”打开对应补问草稿，确认后返回同一任务的新版本。旧版本继续可读。

## 数据与调用

新建产品任务显式使用 clarification 模式。已有任务按其原模式读取和回放。确认记录、暂停恢复、身份隔离、材料读取和费用记录复用现有实现。

需求事项引用原始目标、产品回答、材料和摘要。用户已经明确给出的要求采用逐字来源校验。B 的问题编号限定在当前可询问事项中。C 的交接判断同时核对覆盖范围、未决事项、冲突和当前内容指纹。

新模式的草稿持续保存，供跨日恢复及案例归档。模型失败保留已完成角色与调用记录，未知调用结果沿用原核账保护。

确定的格式错误可以追加一次修正调用，原失败、修正关联与两次费用都留在记录中。已完成的其他角色继续有效。修正成功后，当前阶段显示完成，原失败步骤仍可查看。

## 首例真实任务

首例使用用户当前的方案擂台改造需求。项目代码、页面截图、说明和聊天内容作为材料。原始目标、每轮回答和最终确认采用本人在产品中的实际提交。

当前首例状态为待本人真实任务试用。真实模型技术联调的模拟输入、自动化测试替身和本人任务分别记录。后续同学或客户任务需要实际需求及材料使用同意。

每个案例记录原始需求、各轮问题与选项、产品回答、回答引起的变化、最终需求和执行提示词。执行者追问及用户实际采用或修改的内容在收到实际反馈后追加。当前尚无执行反馈。

## 检查与记录

本轮行为回归覆盖选项、回答驱动分支、PPT 内容、未知与跳过、改答局部失效、分支恢复、跨日保留、陈旧 C 结果防覆盖及旧记录兼容。界面检查采用桌面和手机相同视口，对照原组件层级、类名、容器和动效。

运行以下命令检查实现，具体结果以当次日志为准。

```sh
pnpm typecheck
pnpm lint
pnpm format:check
pnpm test
node --test scripts/*.test.mjs
pnpm build
PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e
```

案例归档方法见本目录的 clarification-case-records.md。公开前需要检查自由文本并脱敏。真实任务的业务验收采用本人在产品中的连续交互和最终交付，程序测试和模型调用记录分别保存。
