# 方案擂台技术报告

## 0.2.0 候选版本草稿

面向学习、生活、工作和创作的条件决策工具。

让三条策略独立提出行动，再围绕具体判断质疑、核验、修订和裁决。用户可以补充材料与限制，保留旧版本后重新推演。

本报告由学生主导整理，使用 AI 辅助设计、开发与文档编写。项目主体、团队成员和指导信息以正式报名材料为准，本稿不代填身份。

## 01　项目目标与阅读范围

方案擂台帮助用户比较可执行的路线。输入可以是目标、已有选项或尚未成形的想法。用户分别填写硬性限制与个人偏好，避免系统把“必须做到”和“最好如此”混为一谈。

典型问题包括学习安排、生活选择、工作方案和内容制作。系统先形成 3 条策略，再让角色围绕具体主张提出质疑。工具返回材料或计算记录，策略据此修订，裁决列出成立条件与下一步行动。

### 阅读导航

| 页码   | 内容                           | 核对重点                       |
| ------ | ------------------------------ | ------------------------------ |
| 3～5   | 产品边界、架构与数据           | 实际实现了什么，状态如何保存   |
| 6～10  | 上下文、质疑、工具、修订与版本 | 结论是否能回到原话和证据       |
| 11～13 | 费用、失败、安全与界面         | 请求是否可控，用户能否理解过程 |
| 14～15 | 真实联调与评测                 | 事实、开发诊断和质量结论的边界 |
| 16～18 | 评分证据、复现与计划           | 材料是否与同一版本对应         |

本稿把“已实现”“已联调”和“待评测”分开陈述。代码中存在接口，不代表真实模型一定成功；自动检查通过，也不等于用户已经验证效用。

### 当前范围

历史 P0 聚焦文字输入、同模型角色协作、材料检索、算术核验与版本重赛。当前开发版另有目标补问、文档和图片附件、5 种模型选择及快速复核，使用说明见 [目标引导、附件与模型选择](guided-input.md)。实现不等于真实验收：每种模型与附件路径须有对应记录。互联网搜索和公开分享仍未实现。

### 本稿的可复现构建

```sh
node scripts/build-technical-report.mjs --version 0.2.0 \
  --output outputs/technical-report-draft.pdf
```

`--commit` 可指定源码 SHA。`--eval-summary` 载入实际汇总，缺省时显示待冻结。`--ui-screenshot` 和 `--ui-caption` 可替换同版本截图。脚本检查 18 页页框溢出，再输出 PDF 与构建元数据。流程可重复执行，不承诺跨机器 PDF 字节相同。

## 02　产品任务与规范样例

用户需要知道每条路线的资源、步骤、第一步和失效条件。只给一个结论，难以检查前提；只给多个候选，也难以判断发生条件变化后该修改什么。方案擂台把这些内容放进同一轮可追溯推演。

### 输入与输出

| 输入         | 约束规则                     | 输出对应           |
| ------------ | ---------------------------- | ------------------ |
| 目标或想法   | 8～3,000 个字符              | 核心思路、行动步骤 |
| 已有选项     | 可留空，最多 3 个            | A、B、C 路线       |
| 硬限制与偏好 | 分别保存                     | 约束比较、条件裁决 |
| 文字材料     | 最多 20,000 个字符           | 材料检索证据与定位 |
| 预算与时间   | 可留空，金额非负、时间大于零 | 投入估算与限制检查 |

### 贯穿样例：90 秒照片视频

规范样例保存在 `src/lib/sample.ts`，导出 `videoChallenge`。目标是在 7 天内，用 12 张已有照片制作 90 秒、1080p、有字幕且无水印的视频。备选路线是模板、本地剪辑和 AI 生成镜头。

总投入上限为 8 小时，包含等待、重试、学习与返工。预算字段为 300 元。3 个合格 AI 镜头曾分别尝试 2、3、4 次，每次 8 分钟。后期 120 分钟只是估计，不是实测。

照片使用权作为合成输入的一部分给出。软件导出权限、无水印条件与订阅价格仍未知。材料明确提示：3 个样本不能代表未来成功率，均值不能当作保证。

页面用 `TEST MATERIALS` 标识样例。点击样例只填写表单，真正开始时才创建任务并调用模型。没有样例结果冒充实际生成内容。

## 03　系统架构与请求边界

应用采用 Next.js、React、TypeScript 和 Zod。服务端使用 Node.js 24 的 SQLite 接口保存状态。模型密钥只在服务端读取，浏览器接收任务快照和事件。

### 模块关系

```text
浏览器表单与三路线界面
        ↓ 同源 JSON 请求 / SSE 事件
Next.js API：访问检查、输入校验、错误映射
        ↓
runtime：步骤认领、预算预留、版本状态与提交
   ↙                ↓                 ↘
SQLite 数据库      模型适配器          确定性工具
版本 / 步骤 / 事件  DeepSeek / OpenAI   材料检索 / 算术 / 限制比较
```

| 主要入口                             | 作用                             |
| ------------------------------------ | -------------------------------- |
| `GET /api/health`                    | 配置状态、应用与协议版本         |
| `POST /api/arenas`                   | 创建有所有者的任务               |
| `POST /api/arenas/:id/advance`       | 推进一个可执行步骤               |
| `GET /api/arenas/:id/events`         | 用 SSE（服务器发送事件）通知变化 |
| `POST /api/arenas/:id/versions`      | 按新条件创建版本                 |
| `POST /api/arenas/:id/interventions` | 围绕具体主张加入用户质疑         |
| `POST /api/arenas/:id/stop`          | 停止后续步骤，保留已产生内容     |

页面只安排一个推进请求。事件到达时读取新快照，模型仍在处理也能显示真实的开始状态。后台工作器默认关闭；启用后由长驻进程认领步骤。页面和工作器共用步骤认领规则，不各自重复发出模型调用。

当前部署设计面向单实例 SQLite。多实例共享数据库和 serverless 后台持续运行均未获得部署验证。

## 04　数据契约与运行状态

`src/lib/contracts.ts` 定义输入、模型输出和页面快照。Zod 校验字段长度、枚举和数组上限。数据库保存独立版本，步骤与事件都带 `versionId`。

| 对象             | 关键内容                                               | 核对关系                |
| ---------------- | ------------------------------------------------------ | ----------------------- |
| Challenge        | 目标、限制、偏好、选项、材料、预算与时间               | 本版本输入              |
| Strategy / Claim | 路线、步骤、资源、主张状态与来源编号                   | 路线 A、B、C；主张有 ID |
| Attack           | 发起方、目标路线、目标主张、原话、原因、影响与核验请求 | 必须指向实际主张        |
| Evidence         | 工具、结果状态、原文、来源、计算与假设                 | 关联攻击 ID             |
| Revision         | 完整修订策略、逐条回应、理由、变化与证据 ID            | 关联路线与攻击          |
| Verdict          | 建议、成立条件、未知、行动、退出条件与逐项判断         | 引用证据与攻击          |
| ArenaSnapshot    | 所有版本、步骤、事件与模型信息                         | 页面读取的完整状态      |

### 两级状态

版本状态包含 `ready`、`running`、`completed`、`paused`、`failed`、`uncertain` 和 `superseded`。步骤状态另有 `pending`、`running`、`completed`、`failed`、`uncertain` 和 `skipped`。

`uncertain` 表示外部请求是否完成尚不清楚。系统保留预留额并停止自动重试，避免把网络中断当作“肯定没有计费”。`superseded` 表示条件已变化，旧版尚未开始的步骤停止执行。

每个新版本保存有效模型配置 `runConfiguration` 与 SHA-256 `configurationHash`。模型、接口、提示词或输出模式等配置变化后，旧版本停止后续步骤，待执行步骤标为跳过；新版本另行固定配置。密钥与密钥配置状态不进入指纹，轮换密钥不改变协议记录。

阶段顺序为独立提案、交叉质疑、证据核验、策略修订和条件裁决。页面进度来自步骤与事件，不用定时播放的预设动画代替后端状态。

## 05　同模型角色与独立上下文

这里的智能体（Agent）指按角色、上下文和步骤执行任务的模型调用单元。A、B、C 使用同一个已配置模型，分别生成策略。独立提案阶段会清空其他路线、质疑、证据和修订，角色只获得当前问题与自身角色信息。三个名字不代表三个独立训练的模型。

### 一轮推演的上下文变化

| 阶段 | 可以读取                     | 目的               |
| ---- | ---------------------------- | ------------------ |
| 提案 | 用户条件、角色与分配选项     | 先形成独立路线     |
| 质疑 | 本轮提案与可引用主张         | 指出对手的失败前提 |
| 核验 | 已校验的攻击和用户材料       | 执行受限工具       |
| 修订 | 本组提案、质疑和真实工具结果 | 修改行动并说明依据 |
| 裁决 | 当前策略、回应与证据         | 给出有条件的建议   |

每个常规条件安排 3 次提案、3 次质疑、3 次修订和 1 次裁决，核验工具由服务端执行。格式修复可能增加请求。实际调用数与用量必须保留，不能只报告计划次数。

### 相似路线的处理

运行时用词法相似度检查可能重复的路线。重复时可以安排受限重试；仍重复的结果不会为凑满三条而补造。界面允许真实结果少于 3 条。

词法检查只能发现部分文字和结构相似。它不能证明策略在语义上独立，也不能保证路线覆盖了全部可行方案。

当前提示词要求各路线保留核实后的本路线实施分支，失效路线明确退出，不统一改成核实清单；这项要求的真实复验待执行。 新增要求还包括换路时累计已投入资源，结论的支持程度限于证据实际覆盖范围；真实复验仍待执行。

同一个模型可能共享错误、偏好与盲点。角色分工与上下文隔离能减少直接复制，不能消除模型相关性。是否改善决策质量，仍需三组对照和人工评分。

## 06　质疑必须指向具体判断

每条策略包含最多 3 个关键主张。主张区分用户提供、估算、未知和有支持材料。攻击必须给出目标路线、主张 ID 与原话，并说明失败机制、影响和核验方法。

### 从原话到核验

```text
具体主张 ID 与原话
        ↓
质疑：哪一个前提可能失效
        ↓
影响：失效后改变哪项选择或行动
        ↓
请求：检索用户材料 / 计算表达式
        ↓
真实证据与策略回应
```

strict-tool 的动态 Schema 只列出当前角色可引用的主张与原话。服务端仍检查主张、原话和目标是否对应，拒绝不存在或错配的引用。提示词要求说明失败机制，但程序不能证明每条理由都有实质。最终裁决保留逐条攻击结论，缺少对应支持证据时降为未决。

攻击结论中的“成立”“反驳”和“未决”，描述裁决对这项质疑的判断。它们并非客观真理标签。证据不足时应保留未决。

### 用户介入

用户点击当前显示的主张，可以补充反例或限制。服务端按照当前版本的有效策略查找原话，必要时创建新版本。旧版主张不能悄悄套进新版结果。

其他路线可以借鉴同一条质疑。界面把这种回应单列为“其他路线借鉴”，展示路线自己的修改。借鉴不代表目标路线接受了对手的全部观点。

用户材料始终作为任务数据传入。材料中的文字不能自动升级为系统指令，也不能代替工具实际执行的结果。

## 07　工具真实性与材料检索

P0 的检索增强生成（Retrieval-Augmented Generation，RAG）只使用用户提供的文字。系统按行切分材料，长片段继续按长度分块。块 ID 包含材料哈希与位置，结果保留原文、行号和字符范围。检索采用分词与词项匹配，不包含向量数据库或互联网搜索。

### 已实现的工具

| 工具               | 实际执行                     | 证据中保留             | 主要限制                     |
| ------------------ | ---------------------------- | ---------------------- | ---------------------------- |
| `search_materials` | 在本版本文字块中匹配查询     | 材料原文、块 ID 与位置 | 未命中不代表事实不存在       |
| `calculate`        | 解析受限算术表达式           | 表达式、数值、假设     | 输入与假设错，结果仍可能无用 |
| `constraint_check` | 比较明确预算、时间与路线估算 | 给定限制、估算与比较   | 估算不是实测，不能证明可行   |

计算器只接受数字、括号和规定算符，不执行任意代码。模型提出工具请求，服务端执行后才产生 Evidence。没有找到材料时，证据状态为不可用；工具出错时保留错误状态。

### 样例中的可核对计算

三个合格镜头共尝试 2 + 3 + 4 = 9 次。已给出的尝试耗时合计为 9 × 8 = 72 分钟。再加后期估计 120 分钟，得到 192 分钟的示例合计。

192 分钟只覆盖材料列出的部分。它不包含所有学习、排队、返工和未来失败。3 个样本无法估计稳定成功率，也不能据此保证在 8 小时内完成。

当前材料还保留 `document`、`model_transcription`、`model_interpretation` 和 `unknown` 来源。文档提取与模型转录、解释分开标记；模型解读不能自行升级为已核实事实。来源不明的片段保留未知，防止模型用自己的推测证明自己的结论。

“存在引用”只证明来源可定位。材料本身可能过时、片面或错误，模型仍需解释材料为何支持当前判断。

## 08　修订、证据回应与条件裁决

修订输出完整策略，并逐条说明接受、反驳或保留未决。每条回应包含理由、实际变化和证据 ID。strict-tool Schema 动态列出本轮实际攻击与证据 ID，修订回应还按攻击绑定候选证据。服务端再次核对同一攻击的关联，避免虚构编号。材料块的 `sourceIds` 与工具记录的 `Evidence.id` 分工不同，回应使用后者。

### 可追溯的修订

| 用户看到的内容       | 保存的数据                        | 说明                       |
| -------------------- | --------------------------------- | -------------------------- |
| 修订前后对照         | 初始策略与 Revision.strategy      | 比较标题、思路、步骤和资源 |
| 第一步与失效条件变化 | `firstAction`、`failureCondition` | 核对行动是否改变           |
| 金额与工时变化       | `estimatedCost`、`estimatedHours` | 始终标为估算               |
| 接受或保留路线       | responses 与 summary              | 保留逐条理由               |
| 裁决中的攻击结论     | `attackFindings`                  | 回到攻击与引用证据         |

页面只列实际值发生变化的字段。没有变化时明确说明保留原行动内容。“已修订”与“已复核”分开显示，不把任何回应都写成接受对手意见。

### 裁决的内容

裁决可以是推荐、并列、依据不足、不可行或阶段性判断。它需要说明当前条件、未决事项、第一步与退出条件。没有足够依据时，系统允许不选出优胜路线。裁决可以引用不可用记录说明未知，但不能据此证明质疑成立。攻击判断须由成功且对应的证据支持。当前修复还会按最终修订路线另核对预算与工时，保留初始核验记录，避免用旧资源估算验证新行动。该修复仍待本轮真实案例检查。

格式和引用检查只能保障一部分协议正确性。文字变化不等于策略改善；引用一个真实证据 ID，也不等于推理有效。程序不能自动证明修改内容已解决全部风险。

已知格式或引用错误可以触发最多 1 次显式修复。修复失败仍保留失败记录。修复请求不得编造缺失结果，费用和用量纳入本轮记录。

## 09　条件变化与版本隔离

修改限制、偏好、材料或预算时，系统创建新版本，并保存修改原因。新版本引用父版本 ID；旧版本继续保留输入、已完成内容、证据和费用。

### 后端隔离

步骤认领与预算预留在事务中完成。模型请求离开事务执行，结果返回后按原 `versionId` 写入。用户期间创建新版，旧请求仍只能记录到旧版，不能污染新条件。

旧版未开始的步骤标记为跳过。已经发出的请求不能撤回，仍可能产生费用。页面选择历史版本时以只读方式展示，避免旧主张继续作为当前目标提交。

### 前端隔离

前端使用独立的串行推进循环。快照更新不会取消循环并漏掉下一步。SSE 事件能在模型请求尚未结束时触发读取，显示真实运行状态。

每次变更递增本地请求代数。变更前的读取或推进响应不能覆盖变更后的页面。对同一任务，前端还比较活动版本号与最新事件序号，拒绝倒退快照。

| 场景                   | 预期处理                       |
| ---------------------- | ------------------------------ |
| 刷新页面               | 用最后一个任务 ID 读取已有状态 |
| 延迟旧响应晚于新版返回 | 拒绝回写新版页面               |
| 两处同时尝试推进       | 原子认领，只执行一个步骤       |
| 用户现在收束           | 取消后续步骤，保留阶段性判断   |
| Cookie 身份丢失        | 提示无法恢复，允许开始新任务   |

## 10　费用、失败与停止语义

历史 DeepSeek 基础配置为 `1.2.1`。当前提示词为 `1.2.7`，Schema 为 `1.1.0`，快速复核协议为 `decisions-review-1.2.0`。模型目录包含 4 种 GPT 与 `deepseek-flash`，同一条件版本固定有效配置。DeepSeek 使用 `/beta` strict-tool，OpenAI 使用 Responses 接口。每次提交限定为一个匹配阶段的函数结果，再经过本地 Schema 与引用校验；模式和接口不符时明确失败，没有自动回退。

服务端根据包含动态 Schema 的实际请求体，在发出调用前预留保守费用与 Token 上界。收到可信用量后记录实际 Token，并按配置单价估算金额。页面区分已记录费用与调用中预留额，数值不冒充服务商账单。

### 失败分类

| 情况                           | 是否自动继续           | 费用处理与用户说明         |
| ------------------------------ | ---------------------- | -------------------------- |
| 合法完成                       | 推进下一步             | 记录实际用量并释放对应预留 |
| 已知 JSON、Schema 或引用错误   | 至多 1 次显式修复      | 原失败与修复都计入用量     |
| 网络超时、响应不完整或用量未知 | 停止自动重试           | 保留预留额，标记 uncertain |
| 本地预算不足                   | 不发出下一次模型请求   | 保留已完成结果             |
| 并发占用                       | 返回当前状态或有限退避 | 不重复认领同一步骤         |
| 用户收束                       | 停止后续步骤           | 已发出的请求仍可能完成计费 |

步骤租约到期时，系统把无法确认的外部调用留为未知，不自动从头再发。错误页面保留可用内容，并说明下一步应核对状态或补充条件。

### 运行与评测分别记账

历史网页与离线评测使用各自账本。当前所有收费入口共用中央账本，并保留应用内记录。发出请求前预留费用与 Token；进程中断后保留未知预留，不能通过删除草稿或重试释放额度。中央账本仍须与服务商账单核对。

历史人民币安排为网页开发 70 元、离线评测 20 元、最终验收至少 30 元，网页单场及历史版本共用 1.5 元。历史协议 `2.1.0` 每个方法轨迹共用 1.5 元、600,000 Token 和 12 次工具请求上限。这些数据保留历史归属。

后续总授权为 200 美元。2026 年 11 月 7 日，用户已批准将本轮累计请求上限调整到 700 次，10 美元、5,000,000 Token 和全部预留保持不变；实际执行以账本审计记录为准。限额变更须留审计记录，环境设置须与账本一致。未知请求不重试；新批次出现未知请求时停止，旧预留只按已记录审计基线承认，不代表核销。

费用预估有误差。缓存计费、时段价格、汇率或模型别名变化，都可能使服务商账单不同。

## 11　访问隔离、数据与安全边界

生产预览默认要求访问口令。口令用于限制进入付费推演，所有者身份用于隔离不同浏览器的任务，两者承担不同职责。每个任务读取、推进、修改和停止操作都校验所有者。

### 当前控制

| 位置       | 已实现控制                        | 仍需注意                             |
| ---------- | --------------------------------- | ------------------------------------ |
| 浏览器身份 | 签名 HttpOnly Cookie              | 无账号找回；清除 Cookie 可能丢失访问 |
| 请求入口   | 同源检查、输入长度与枚举校验      | 反向代理需保留可信 Host              |
| 模型接口   | 服务端密钥、HTTPS、拒绝任意重定向 | 外部模型服务仍能看到提交的数据       |
| 工具       | 受限算术、只读文字检索            | 不具备开放网络和任意代码权限         |
| 发布包     | 允许列表、密钥形态扫描、路径检查  | 扫描不能代替人工密钥管理             |
| 运行限制   | 任务次数、并发与预算约束          | 公开演示仍需检查真实流量             |

用户应只提交有权使用的材料。当前样例是合成数据，不能据此推断系统已经通过真实敏感数据审计。单实例数据库与备份由部署者管理，公开部署前需明确数据保留与删除办法。

模型可能受到材料中的误导指令影响。应用把材料标为结构化任务数据，限制工具范围，并校验输出引用。这些控制不能保证完全抵御提示注入。

本产品提供比较与行动建议。医疗、法律、财务等高风险问题仍需专业核实。当前 P0 没有对这些领域做效用或风险验证。

发布材料不得包含密钥、私有环境文件、数据库、会话 Cookie 或匿名评分身份映射。
