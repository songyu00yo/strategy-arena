# 需求澄清案例归档

## 先在产品中完成交互

本人任务从产品输入目标。问题、选择、补充、确认和后续修改都保存在同一份产品记录中。聊天里提供的目标可以作为输入素材，聊天答复需要本人在产品中提交后，才能计入产品确认记录。

案例采用以下三类标记。

| 标记                   | 记录内容                                       |
| ---------------------- | ---------------------------------------------- |
| `real_task`            | 本人的实际任务，回答已经保存在产品中           |
| `simulated_real_model` | 明确标注的模拟场景，模型调用及用量保存在产品中 |
| `test_double`          | 自动化测试使用的模型替身与合成回答             |

导出者根据实际来源选择类别。工具会检查产品记录是否存在。`real_task` 要求已有保存的回答，`simulated_real_model` 要求已有模型用量记录。工具会注明类别来自导出者声明，保留已有问题、答案和调用记录，无法核实回答者的现实身份或服务商是否实际完成网络请求。

## 导出已有记录

在项目工作区运行以下命令。数据库参数使用实际的产品库路径，草稿编号取自产品请求或运行记录。

```sh
node scripts/export-clarification-case.mjs \
  --database /absolute/path/product.sqlite \
  --intake DRAFT_ID \
  --case-type real_task \
  --out /absolute/path/new-case-export
```

工具以只读方式打开 SQLite，读取指定草稿、同一所有者的关联任务版本、相关模型调用和已有反馈。运行过程加载已有产品记录，模型请求数为零。命令生成 `case.json` 和 `case.md`，并保留原目录中的历史导出。已有输出目录会提示更换路径。

导出包含原始目标、每轮问题和答案、确认状态、A/B/C 调用摘要、轮次变化、交接审查缺口、需求说明和执行提示词。JSON 还保留已存的用量、失败与未知调用状态。

执行反馈只采用产品中保存的记录。没有记录时，导出显示“尚无产品保存的执行反馈”。执行者补问、用户采纳和用户改动分别保留原类别及来源。

## 脱敏与分享

工具省略所有者标识、模型私有配置和附件原始字节，将任务、草稿、调用和附件编号转为稳定别名。自动脱敏覆盖常见邮箱、手机号、证件号和凭据格式。

人名、单位名、项目代号等私有词语可以放入 JSON 字符串数组。

```json
["需要隐藏的人名", "需要隐藏的单位名"]
```

导出时追加词表路径。

```sh
node scripts/export-clarification-case.mjs \
  --database /absolute/path/product.sqlite \
  --intake DRAFT_ID \
  --case-type real_task \
  --out /absolute/path/another-case-export \
  --redact-file /absolute/path/redaction-terms.json
```

分享前检查 Markdown 和 JSON 中的自由文本。自动脱敏依靠固定格式与词表，无法识别全部私有信息。导出文件默认权限为 `0600`。

## 验证记录

`node --test scripts/export-clarification-case.test.mjs` 使用临时合成数据库，检查只读导出、分类、脱敏和反馈保留。业务回归使用明确标注的模型替身。具体检查结果以本次运行日志为准。

本说明只提供归档方法。实际案例、真实模型效果和执行反馈需要分别取得产品记录后归档。
