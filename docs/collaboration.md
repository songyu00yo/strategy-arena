## 分工与共同目标

用户已确定：Claude 主要负责前端视觉和独立评审；Codex 负责竞技机制、后端可靠性、测试、版本管理及最终集成。Claude 由用户手动打开，不通过 Codex 自动创建会话或调用 Claude API。

双方共同维护《方案擂台》的真实竞技体验。优先完成 P0 的语义可靠性和真人验收。P1 只在 P0 验收通过后推进，不以视觉调整为由加入模拟策略、预写反转或生产假数据。

开始前阅读 [完整交接](handoff.md)、[项目规则](../AGENTS.md)、[Claude 入口](../CLAUDE.md)。Next.js 16.4.5 的行为以安装包内文档为准。

安装与启动：

```bash
# 在自己工作区执行；Node.js 24.19.0，pnpm 11.19.0。
pnpm install --frozen-lockfile
node scripts/dev-local.mjs claude
# Codex 使用：node scripts/dev-local.mjs codex
```

该启动器强制禁用模型密钥与后台执行，并覆盖继承的数据库和会话配置。页面应显示“模型待配置”。这不是故障，不要为了看见策略而接入真密钥或增加生产假数据。用现有 Playwright 测试替身检查策略、证据、修订和重赛画面。

同一主机不同端口仍可能共享 Cookie。开发预览使用独立浏览器资料或 Playwright 隔离上下文，不在真实预览的浏览器资料中创建开发挑战。测试替身只代表交互检查，截图必须注明。

停止开发服务时，在启动终端按 `Control-C`。不要按进程名称批量停止 Node.js，也不要停止 3200 端口的固定预览。

## 共享任务与同步

共享目录位于主工作区 `work/collaboration`，不进入 Git。可以从任一工作区定位：

```bash
COMMON_GIT=$(git rev-parse --path-format=absolute --git-common-dir)
ARENA_SHARED="$(dirname "$COMMON_GIT")/work/collaboration"
cat "$ARENA_SHARED/tasks.md"
cat "$ARENA_SHARED/codex-status.md"
cat "$ARENA_SHARED/claude-status.md"
```

`tasks.md` 由 Codex 维护。双方只更新各自的状态文件，减少同时写入冲突。需要较长评审时，分别新增带任务编号的评审文件，并在自己的状态文件中引用。

状态记录包含：任务编号、状态、实际工作区和分支、基线提交、最近提交、完成内容、检查命令与结果、待协调问题、下一步。状态取值为“未开始、进行中、待评审、待协调、完成”。未运行检查就写“未执行”，不从历史记录复制“通过”。

在开始任务、发现阻塞、完成提交、交付评审时读取共享记录并更新自己的状态。共享文件不是消息推送服务；对方没有运行或没有读取时，不能宣称消息已送达。用户首次粘贴启动指令后，Claude 应先在自己的状态文件中确认接手。

需要长期保存的结论写入 PR 说明、版本化文档或脱敏验收工件。临时协作文件不能替代 Git 历史和最终证据。

## 首轮任务

### Claude：CLAUDE-UX-001

先阅读当前页面与交接，给出简短问题清单，再实施拥有范围内的改进。优先改善三条策略轨道、被攻击主张、证据状态和修订前后的关联。保留暖白、墨黑、钴蓝与少量朱红的方向，使用文字和形状共同表达状态。

桌面至少检查 1440 × 900，手机至少检查 390 × 844。证明用户能找到当前争议、打开证据、看懂实质变化、修改条件并识别历史版本。补充键盘、焦点、减少动效、加载及失败状态检查。

交付实际代码提交、截图、测试日志和未解决问题。禁止用新概念稿代替实现，不加入排行榜、分享、截图识别等 P1。不要为视觉演示修改模型结果。

### Claude：CLAUDE-REVIEW-001

独立评审 Codex 的迁移、开发隔离工具与后续 P0 修复。记录文件和位置、严重程度、触发条件、证据、建议及是否阻断合入。后端问题只提评审，不越过归属修改。没有发现问题时说明审查范围与未覆盖项。

### Codex：CODEX-REL-001

先复核历史记录中的文字限制和时间表达问题，区分已完成的规则修复与仍未验证的模型语义。依据可复现问题补充回归检查。新模型运行先核对累计账本与预留；本次迁移不追加收费评测，不改写冻结数据。该任务的实现与后续验收单独记录。

## 提交、评审与集成

Claude 可以在自己的短分支上提交，这是平级协作者的授权。Codex 临时派出的子代理仍遵守主代理统一提交的规则。双方提交采用 Conventional Commits，一次提交对应一个可解释的改动。

Claude 完成后在共享状态写明完整提交 SHA 和检查结果，可以推送自己的分支，但不合并 `main`。Codex 查看实际差异、复核测试、处理接口影响，并通过 PR 和必需的 `validate` 检查集成。禁止强推公开历史、覆盖标签或直接改服务器源码。

检查顺序：

```bash
pnpm typecheck
pnpm lint
pnpm test
node --test scripts/*.test.mjs
node scripts/validate-evals.mjs
pnpm build
# Claude 工作区使用 3101；根目录省略 E2E_PORT，默认 3100。
E2E_PORT=3101 pnpm test:e2e
```

如果本机只有 Google Chrome，可以加 `PLAYWRIGHT_CHANNEL=chrome`。CI 使用 Chromium。构建后源码、提交或产物发生变化时，要重新构建后再运行会打包的浏览器测试；不要篡改构建身份文件。两边依赖分别安装，测试数据分别保存。

合并完成后由 Codex 协调下一轮分支。Claude 先保存并提交自己的工作，再执行已确认的分支更新。不在存在未提交修改时自动重置。所有对外发布及真实模型总账由 Codex 汇总，单个工作区的额度不代表新增预算。
