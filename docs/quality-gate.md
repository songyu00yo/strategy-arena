# 本轮内部质量门槛

## 目标与状态

本门槛用于判断当前候选能否进入材料冻结，以全国一等奖为努力目标。它不是官方评分表，也没有固定获奖分数线。获奖取决于正式评审、现场表现与其他参赛作品，不能提前承诺。

截至 2026 年 11 月 7 日，本轮修复仍待完整验收。已有测试、历史真实运行和代理审查各有范围，不能合并写成“全部通过”。本轮没有完成真人评分、公网验收或最终材料冻结。后续结果以带源码身份和运行时间的实际报告为准，不在本文预填通过状态。

## 冻结前的阻断条件

以下任一项不满足，就保留候选状态，先修复或补证据，再冻结。

| 范围     | 必须达到的条件                                                         | 应保存的证据                                                           |
| -------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 代码审查 | 跨审中发现的 P0、P1 问题逐项复现、修复并复核；新增修改再审影响范围     | 问题位置、触发条件、严重程度、修复与复核记录；说明审查者是真人还是代理 |
| 免费检查 | 当前源码通过类型、规范、相关单元和脚本检查；构建后通过浏览器检查       | 命令、时间、实际数量、失败记录、完整 SHA 和源码状态                    |
| 真实案例 | 冻结输入下检查硬限制、来源、行动与版本变化；失败和未跑项保留在分母     | 输入哈希、模型与配置、原始输出、处理后结果、证据与逐项结论             |
| 费用安全 | 所有入口共用中央账本，限额一致；新未知请求立即停止新批次，不重发原请求 | 调用前后用量、预留、失败与修复、审计记录；不暴露密钥                   |
| 界面交互 | 桌面和 390 px 窄屏可完成主流程；键盘、焦点、减少动效、错误恢复可用     | 实际浏览器记录，注明测试替身和真实服务边界                             |
| 材料一致 | 视频、PDF、截图、仓库与发布清单对应同一冻结 SHA                        | 完整 SHA、构建身份、文件哈希、视频来源与完整观看记录                   |
| 对外声明 | 功能、测试、模型语义、真人效果与部署状态分别有证据                     | 可核对出处；未实现、未运行和未知项明确列出                             |

P0 指费用失控、数据隔离失效、不可恢复的已提交数据丢失或主流程不可用等阻断问题。P1 指会误导决策、违反硬限制、伪造来源或使关键操作失效的问题。代理之间的多轮 review 属于辅助审查，不等于真人评审，也不能据此生成用户评分。

## 冻结真实案例

先固定案例、条件版本、模型选择、输入哈希与通过标准，再发出收费请求。查看结果后修改输入或提示词，需要作为新候选保留，不能覆盖失败记录。案例来自合成任务时必须标明，不能写成真实用户成效。

| 核对项     | 通过条件                                                                 | 阻断示例                                     |
| ---------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| 硬限制     | 推荐路线的行动、预算、工时与明确限制一致；冲突时说明不可行或需要调整条件 | 要求真实素材却继续生成虚构画面；行动时间超限 |
| 来源       | 引用可定位；区分用户文字、文档提取、模型转录、模型解释和未知             | 将模型解释当原文，再用同一解释证明模型结论   |
| 行动       | 给出可执行的第一步、成立条件与退出条件，关键事实缺失时明确未知           | 只有泛泛建议；无依据地保证成功或可行         |
| 修订       | 回应关联真实攻击与证据；有实质变化时说明变化，没有变化时如实保留         | 虚构证据 ID；把任意文字变化称为质量提升      |
| 条件版本   | 新条件另建版本，旧输入与结果可读；最终资源按修订后路线复核               | 新版沿用旧资源判断；旧响应覆盖新条件         |
| 边界与失败 | 材料不足、条件冲突、未配置、预算不足和未知请求有明确结果                 | 用测试替身填补生产结果；未知请求自动重试     |

本轮计划检查 8 个条件版本：目标引导后使用 DeepSeek 完整推演；职业任务两版；创作任务自动模式两版；消费任务自动模式两版；条件冲突边界一版。预计常规请求约 81～83 次，格式修复等额外请求也计入总限额。计划不是已执行结果；任一版本未完成，都保留原定分母和实际停止原因。每版须核对实际选择的模型，不能把自动模式当成固定供应商。

5 种模型、不同附件类型和图片辨读路径的实现，不能由上述 8 个版本一概证明。没有对应真实调用的能力继续标为待验收；明确使用 DeepSeek 的记录不能算作 GPT 验收。旧三组对照保留原配置、失败和空缺评分，不据完成率宣称优于强单助手或 GPT。

## 费用与未知请求

截至 2026 年 11 月 7 日，本轮累计上限为 10 美元、650 次请求和 5,000,000 Token，三项同时生效。启动本轮修复后的回归前，已记录 545 次请求、3,573,097 Token；这是起始快照，不是后续实时余额。既有 4 笔 held 预留合计 0.107802 美元，仍未核销。新请求按中央账本实时剩余额度决定是否允许，不能只用计划次数减算。

旧 held 只能按已记录的审计基线明确承认，用于隔离旧未知请求。承认不释放预留，也不授权重试。出现新的 held、reserved 异常或账本不一致时，停止发起新批次并保留诊断；不得删库、换账本路径或手改记录释放额度。实际账单未知时继续标为未知。

## 浏览器与恢复

至少检查桌面 1440 × 900 和窄屏 390 × 844。保留现有亮色视觉与动效，确认减少动效偏好生效。主要按钮、模型选择、补问、摘要、证据抽屉、历史与条件重赛须能用键盘操作，焦点可见、顺序合理，关闭对话框后能返回触发位置。

刷新、切换模型和跨标签页是单独验收项。补问回答先保存再切换；刷新恢复未提交回答；标签页不串草稿；跨面板补充内容不会因面板切换丢失。保存失败、服务端冲突和网络中断须有可理解的提示，不能显示为已保存。模型调用未确定完成时保留原任务和费用状态。

测试替身验证交互和故障分支；真实模型运行验证本次实际输出。录屏必须说明使用哪一种。自动化浏览器通过不能代替真实读屏器或真人任务评价。

## 材料与公网分别验收

冻结前核对仓库、视频、PDF、截图及发布清单的完整 SHA。源码或提交改变后重新构建，不能沿用旧产物身份。历史 `v0.2.0` 附件保留原归属，不能当作当前候选的新证据。最终 `v1.0.0-provincial` 标签在材料核对后创建，并保持不可变。

材料验收至少包括视频时长、分辨率、普通话说明、PDF 页数、操作与结果对应，以及完整播放检查。宣传片有单独用途，时长不足的短片不能代替正式比赛视频。真人评分须记录实际参与方式、评价标准和失败情况；未邀请真人时保持未完成。

公网验收另外要求真实 HTTPS 地址、健康信息、真实流程、访问隔离、错误与费用保护记录。构建包、部署模板、本机页面和 GitHub Release 都不能单独证明公网可用。线上 Demo 是可选加分材料，不用虚构地址补齐。
