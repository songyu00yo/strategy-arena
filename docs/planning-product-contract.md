# 方案擂台产品与交互要求

## 产品终点

用户提出想法，系统帮助判断是否可行，整理制作路径。交付是一份用户读得懂、后续能落实的分析。系统不在这个流程中代建网站、购买服务或部署项目。

用户看到的是系统对项目的理解、关键取舍、可行性结论、制作建议和未决事项。内部提示词、模型指令、请求标识和内容指纹不进入产品界面，也不进入用户复制、下载的分析。

报告可以得出可行、有条件可行、不可行或信息不足。用户采用报告，表示采用这份分析，不表示已经确认每个 AI 建议或满足全部制作前提。

## 有边界的提问

首轮最多发出 8 个关键问题。问题额度由服务端计算，未知、跳过、撤回不退回已使用的发问额度。界面显示本轮已答数量、额度和当前阶段，不把不断增长的版本号当作进度。

系统优先确认会改变可行性或制作方向的条件。登录方式、备份期限、字段校验等实现细节，可作为后续制作建议或待核对条件。用户没有要求深入时，不以这些细节延长当前问答。

用户可以提前生成分析。达到本轮上限或提前结束后，系统自动完成可行性、制作路径和报告整理。报告交付后停止自动提问。需要继续时，用户显式开启最多 3 个问题的补充轮次。

问答上限不意味着未知信息自动变成已知。缺少资源、时间、材料或关键条件时，报告保留未知并说明影响。

## 五个实际角色

| 角色 | 工作                                             |
| ---- | ------------------------------------------------ |
| A    | 理解目标、整理已有信息和关键事项                 |
| B    | 提出影响方向的取舍与具体选项                     |
| D    | 检查资源、时间、成本、限制和风险，形成可行性判断 |
| E    | 整理最小可行版本和制作路径                       |
| C    | 交叉检查并形成给用户的分析报告                   |

角色状态和成果来自实际服务端工作。公开摘要和可读的流式输出可以展示；内部推理、系统提示词不能展示。未运行的角色显示工作范围与已有相关资料，不冒充已经完成分析。

## 首页与操作

首页主文案为“你想做些什么？”。保留输入和开始动作，删除重复说明与标语。创建任务只保存状态；工作台显示后再请求首次分析。

单选题没有默认答案。用户点击选项或明确按键确认后，自动保存并进入下一题。键盘箭头移动焦点不能触发提交。多选、数字和自由文字保留一个“继续”动作。

保存失败保留输入并提供重试。结果未知时先核对原请求，不能创建另一个操作重复提交。成功回执必须对应服务器的真实保存事件。

## 工作台与信息密度

保留原版纸张、墨色、印章、字体和红蓝金配色。重新组织版式：紧凑案卷栏、阶段轨道、五个可读的 Agent 工作面板、当前分析和历史档案。

每个面板展示当前任务、公开输出、已有摘要、相关事项和最近记录。信息密度来自真实内容，不用假数字、伪日志和大段套话填充。无结果时保留用户原始想法和真实工作状态。

历史采用可检索、按角色筛选、逐行展开的档案结构。用户能看到此前的提问、实际回答、分析变化和依据。内部操作标识不直接显示。

进度展示实际阶段、问题额度和分析覆盖情况。不编造百分比、倒计时或预计结束时间。七个检查方面为目标、资源、时间与成本、限制、风险、制作路径和最小可行版本。

## 问题纸与动效

问题仍在工作台右侧展开，保留来源和返回落点。窄屏使用适合阅读的纸面抽屉。单选后的连续问题采用短接力，文字和输入不能被长动画阻塞。

纸张运动保持轨迹、厚度、层次和落点反馈。处理投影结束姿态、回执高度变化及动画取消，避免突然跳变。大面积阴影不逐帧重绘。打开问题时，后台工作可以继续显示公开进展。

Agent 联动表达实际发起、完成和交接事件。不能为了画面热闹伪造工作。刷新、重连与轮询不重播旧事件。减少动效模式下仍可完整操作。

## 分析报告

用户报告优先说明：我们如何理解这个项目、可行性结论、成立条件、最小可行版本、制作顺序、风险和需要补充的信息。用户原话、AI 建议与未知保持各自身份。

报告提供简洁的复制、下载和采用动作。采用操作绑定当前报告及其内容指纹，过期请求拒绝。用户补充新条件后，旧报告保留历史身份，重新生成的报告不沿用旧的采用状态。

## 验证要求

1. 首次模型返回前能看到五角色工作台，内容来自真实状态。
2. 单选自动保存，不默认选答案，不因双击重复写入。
3. 文字、多选和数字不会因一次焦点变化误提交。
4. 首轮最多 8 题，补充轮次最多 3 题；提前生成会自动进入分析阶段。
5. 报告后停止自动推进，未决信息不因用户采用报告而消失。
6. 当前公开输出、历史和来源可读，产品界面及用户导出不包含内部提示词。
7. 桌面与手机完成同一核心流程，减少动效和键盘操作可用。
8. 保存失败保留输入，刷新不重复创建、提交或播放历史事件。

模型替身用于检查交互和状态，不证明真实模型分析质量。真实模型案例和生产部署仍需单独记录。
