# 新工作台真实模型验收

## 验证范围

`scripts/live-planning-acceptance.ts` 用固定的合成输入，调用当前生产 planning 服务，记录 A、B、D、E、C 的实际输出、用量和错误。它验证从创建项目到提前生成分析的运行链路。

这是维护者工具。界面、复制和下载仍只提供面向用户的项目分析；本工具生成的私有 JSON 证据不进入用户报告。

运行器不会代替用户回答问题、采用报告或开启下一轮。遇到待答问题时，它调用已有的 `preview` 动作，保留未知事项，再完成可行性、制作路径和报告整理。因此，运行成功不等于真人交互验收或模型语义质量通过。浏览器行为由独立页面测试验证，语义质量仍需人工阅读实际输出。

## 默认只查看计划

在仓库根目录运行：

```sh
node --import tsx scripts/live-planning-acceptance.ts
node --import tsx scripts/live-planning-acceptance.ts --case portfolio --model-mode gpt-6.1-terra
```

不加 `--run` 时，两条命令都只打印计划：不加载私有环境文件、不打开或初始化数据库、不写结果、不调用模型。`--out` 本身不会开启真实执行。

案例来自 [固定输入](../evals/planning-acceptance.json)：

| 案例           | 输入特点                                                           | 人工检查重点                                                     |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------- |
| `portfolio`    | 个人作品网站，已给出技能、内容、12 小时投入、两周期限和 300 元预算 | 保留原始边界，给出可行性与制作路径，不能擅自增加登录、付费或后台 |
| `unclear-goal` | 只有整理学习资料的工具想法，关键条件尚未确定                       | 保留未知，允许信息不足或条件性结论，提出最小验证办法             |

案例是工程验收输入，不是用户项目或用户反馈。修改输入后，输入哈希随之变化，旧输出不能作为新输入的验收结果。

## 真实执行的准备条件

执行前，需要满足以下条件：

1. 使用 Node.js 24，安装冻结锁文件中的依赖；源代码已提交，工作区干净。
2. 明确选择单个案例和模型。`--model-mode` 使用应用支持的模型值，拒绝 `auto`；记录会同时保留最终解析的有效配置。
3. 配置可用的服务端模型密钥。运行器不加载 `.env.local`，只使用启动进程已有的环境变量。不要在命令参数中填写密钥。
4. 将 `ARENA_DATABASE_PATH` 设为用于本次验收的业务数据库绝对路径，并先准备好它的父目录。该数据库必须与费用账本分开。
5. 将 `ARENA_BILLING_DATABASE_PATH` 指向已有共享账本，费用、请求数和 Token 限额与该账本最新审计值一致。不存在或无效的账本不会由本工具新建。
6. 共享账本中没有 `reserved` 或 `held` 请求。若有，先核对原请求和服务商用量；不能清空预留、换账本或换目录绕过。
7. 使用尚不存在的 `artifacts/NAME.json` 输出路径。`NAME` 只用英文字母、数字、下划线、连字符或点，首字符为字母或数字。

工具检查数据库实际路径，也拒绝把同一个文件的符号链接或硬链接分别当作业务数据库和费用账本。真实调用继续使用生产服务原有的请求锁、配置检查和预算预留，不另建一套模型请求实现。

## 执行一个案例

当环境变量已经由本机的私有配置正确提供时：

```sh
node --import tsx scripts/live-planning-acceptance.ts \
  --run \
  --case portfolio \
  --model-mode gpt-6.1-terra \
  --out artifacts/planning-portfolio-terra.json
```

如果需要由 Node.js 读取已有的私有配置文件，可以显式指定它；将路径替换为实际绝对路径，不要创建含有重复账本或新额度的替代配置：

```sh
node --env-file=/absolute/path/to/existing-private.env --import tsx \
  scripts/live-planning-acceptance.ts \
  --run \
  --case portfolio \
  --model-mode gpt-6.1-terra \
  --out artifacts/planning-portfolio-terra.json
```

这里的模型标识对应仓库内的模型目录，不代表服务商不可变快照。更换模型或输入应作为另一条可区分的运行记录；开始前仍需核对上一条记录和现有账本。

每次只运行一个案例。不要把多个模型、多个案例或失败重试放进自动循环。

## 请求上限与停止规则

创建项目不调用模型。正常流程先执行 A、B；如果 B 提出问题，`preview` 可能再执行一次 A，然后继续 D、E、C。因此，五个角色完成不代表恰好调用五次。典型路径为 5 次或 6 次，实际次数以调用记录和账本为准。

本工具最多派发 8 个模型动作，并在每次派发前检查从本次起点开始的共享账本请求增量。当前 planning 生产路径每个推进动作最多发出一次模型请求，没有自动格式修复重发。账本中其他任务的同期新增请求也会占用这个保守的 8 次窗口；中央账本原有的费用和 Token 限额继续生效。达到上限但尚未形成完整报告时，运行立即停止。

以下情况也会停止：

- 请求处于工作中、待确认或结果未知，或账本出现未结算预留。
- 模型、服务或格式校验失败。
- 源码、有效模型配置、数据库路径或账本策略发生变化。
- 流程偏离首轮分析、出现自动代答或开启第二轮。
- 报告缺少所需角色、实际用量或对应当前内容的审查记录。

每个动作的 `operationId`、版本和完整载荷都在调用前写入记录。异常后保留原记录和原请求，不自动重试，不重新生成请求编号续跑。当前版本不支持 `--resume`，也不覆盖已有输出。若进程中断，先用记录中的原请求核对数据库及服务商状态，不能因为本地没有收到返回就当作没有计费。

## 结果如何解读

输出保存在被 Git 忽略的 `artifacts` 目录中，文件权限为 `0600`。写入使用临时文件与原子替换，输出锁防止两个进程同时写入同一份记录。

| 字段或内容                                      | 含义                                                                |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| `provenance`、`fixtureSha256`、`inputSha256`    | 源码提交、文件哈希、Node.js 版本、固定输入和选中案例的身份          |
| `configuration`                                 | 解析后的模型及 planning 协议配置，不含密钥                          |
| `operations`                                    | 每次操作的原始编号、载荷及是否返回                                  |
| `snapshots`                                     | 每次返回的项目状态和公开事件，包括待定事项与报告                    |
| `calls`                                         | 该会话实际的 `planning_calls`，含角色、预留、用量、结构化输出及错误 |
| `ledgerBefore`、`billingBefore`、`billingAfter` | 账本审计与费用汇总，不是独立充值额度                                |
| `failures`、`failureCode`                       | 停止原因；失败记录保留，不改写为成功                                |
| `case.status = structurally-complete`           | 五角色、当前版本报告与必要记录完整，仅表示运行结构通过              |
| `semanticAcceptance = not-reviewed`             | 模型内容尚未经过人工评价                                            |
| `browserAcceptance = not-run-by-this-script`    | 该工具没有执行浏览器验收                                            |

这是私有工程证据，不是脱敏报告。记录可包含内部的 `executionPrompt`、原始 Markdown、项目输入及结构化输出；不要直接提交、公开或提供给终端用户。工具不生成面向用户的 Markdown。用户界面及其导出继续使用现有的报告展示层，隐藏内部提示词。

运行器保存生产服务已持久化的结构化输出，不保存服务商完整 HTTP 原始报文。账本前后差值可能包含其他任务的同期用量；本案例的调用量应结合其 `calls` 核对，不能直接把全部差值归给本案例。

## 人工复核

读取实际输出后，分别记录以下判断，不把结构通过直接改写成整体通过：

- 是否正确理解目标，并保留原始约束和范围。
- 是否区分用户决定、模型建议、估计和未知；提前生成后是否仍保留未答问题的影响。
- 可行性结论是否有依据，条件不足时是否承认无法判断。
- 最小版本、第一步和制作路径是否可执行，验收方法是否能由用户核对。
- 是否虚构已经完成的制作、部署、测试或外部事实核验。
- 用户页面、复制和下载是否只展示项目分析，不混入内部指令。

真人回答、报告采用、窄屏操作、动效和真实 HTTPS 环境仍需各自验收。旧版演示、三组评测和 `v0.2.0` 记录不能替代这些检查。
