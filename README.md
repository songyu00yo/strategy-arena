# 方案擂台

## 这个项目做什么

当前开发版帮助用户从一个想法出发，判断项目是否可行，整理制作路径。A 理解目标，B 提出关键取舍，D 检查可行性，E 安排制作路径，C 整理项目分析。用户只看到面向自己的理解、结论、建议与未决事项；内部提示词不进入界面和用户导出。

新建任务默认进入分析工作台。创建不等待模型分析，五个 Agent 的工作面板先出现。问题在右侧纸窗展开，单选点选后自动保存。首轮最多 8 题，也可提前生成分析；后续每轮最多 3 题，由用户主动开启。纸张、墨迹、印章、字体和色彩沿用 Opus 原版，工作台改为高密度面板与可浏览档案。旧版保留在 `/?legacy=1`，已有 `/?arena={id}` 链接继续打开旧记录。

五角色工作台于 2026 年 11 月 16 日通过 [PR #20](https://github.com/songyu00yo/strategy-arena/pull/20) 合入 `main`。重构以用户提供的 Opus 原版 `d440adba40bb59f8236d7b7166d4fab0bac81966` 为基线。当前实现范围见 [需求工作台要求](docs/planning-product-contract.md) 与 [接口约定](docs/planning-interface-v1.md)。源码检查与 Chromium、WebKit 页面测试已通过；真实模型质量和生产部署仍需单独验收。

历史预览版本为 `0.2.0`，对应不可变的 `v0.2.0` 发布记录。目标补问、附件提取、条件重赛与快速复核属于保留的旧版推演流程，不能代表新工作台的验收结果。真人评测、公网验收和省赛封版尚未完成；代码测试、测试替身、真实模型运行与真人评价分别记录。

本轮以全国一等奖为努力目标，执行 [内部质量门槛](docs/quality-gate.md)。门槛用于决定是否可以冻结材料，不对应官方固定获奖分数线；奖项取决于正式评审，项目没有获奖或模型优越性承诺。

独立负责人为 `songyu00yo`，开发使用 Codex 等 AI 工具辅助。

## 接手与开发

当前需求工作台由同一开发方统一推进前后端、动效、测试与集成，不需要用户协调外部 GPT 6.1。以下协作目录与 Claude 分工保留为既有工程的历史工作方式；新流程以本节及需求工作台文档为准。

新协作者先读 [完整交接](docs/handoff.md) 和 [协作约定](docs/collaboration.md)。Claude 的入口为 [CLAUDE.md](CLAUDE.md)，负责前端视觉和独立评审；Codex 负责后端、可靠性、测试和集成。

本机项目已迁入文档目录的 `传智杯AI Web`。Claude 使用独立的 `work/claude-frontend` 工作区。视觉开发运行 `node scripts/dev-local.mjs claude`，Codex 使用 `codex` 参数；模型调用默认禁用，端口和数据库互相独立。下面的常规启动步骤用于自行配置真实服务，不用于 Claude 的无密钥视觉开发。

## 本地启动

需要 Node.js `24.19.0` 和 pnpm `11.19.0`。数据库使用 Node.js 内置的 `node:sqlite`，请使用 Node.js 24。

```sh
npm install --global pnpm@11.19.0
pnpm install --frozen-lockfile
test -e .env.local || cp .env.example .env.local
```

已有 `.env.local` 时不要覆盖。用编辑器填写 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`、会话密钥，以及共享账本的绝对路径 `ARENA_BILLING_DATABASE_PATH`。配置说明见 [模型与费用](docs/model-budget.md)。实际限额、已用额度和未结算预留以现有共享账本的最新审计记录为准，文档中的历史数字不代表当前余额。接入已有账本时，将 `ARENA_BILLING_USD_LIMIT`、`ARENA_BILLING_REQUEST_LIMIT` 和 `ARENA_BILLING_TOKEN_LIMIT` 设为该账本的审计值；只改环境变量不能升额。首次安装使用 `.env.example` 的保守初始限额；已有账本不能通过新建账本、复制数据库或换目录重置费用和预留。

会话密钥可以在本机生成：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
pnpm dev
```

在浏览器打开 [本地应用](http://127.0.0.1:3000)。密钥只放在服务端环境文件中。填写后的 `.env.local` 已加入忽略规则；不要提交、截图或粘贴密钥。更改环境配置后重启服务。

各启动入口的用途如下。首次使用仍需先完成依赖安装；真实服务还需完成上述配置。

| 入口                                        | 地址或端口                        | 用途                                                            |
| ------------------------------------------- | --------------------------------- | --------------------------------------------------------------- |
| `pnpm dev`                                  | `http://127.0.0.1:3000`           | 当前源码，默认进入五角色工作台                                  |
| 双击 `scripts/local/启动当前工作台.command` | `http://127.0.0.1:3000`           | macOS 上启动当前源码，不切换版本或重装依赖                      |
| `node scripts/dev-local.mjs codex`          | `http://127.0.0.1:3000`           | 隔离开发数据库，禁用模型调用                                    |
| `pnpm demo`                                 | `http://127.0.0.1:3002/?legacy=1` | 旧版合成演示，不能验收新工作台或真实模型                        |
| 旧的 `scripts/local/启动本地预览.command`   | `http://127.0.0.1:3200`           | 固定历史预览，不自动切到当前版本                                |
| `node scripts/start-live-preview.mjs`       | 默认 `http://127.0.0.1:3340`      | 当前 standalone 构建；准备条件见 [部署说明](docs/deployment.md) |

同一端口的入口不能同时运行。启动脚本不会替你终止已有进程。

模型选择和输出协议以当前源码及 [模型配置](config/model.json) 为准。新工作台使用独立的 planning 协议，旧版的提示词、Schema 版本和三路线记录不能混作新工作台证据。模型别名不代表不可变快照，运行记录同时保留有效配置、服务商实际返回的模型标识与用量。

缺少模型密钥时，页面显示配置提示，实际模型调用返回配置错误；生产路径不会生成模拟回答。

真实模型可能返回不符合约定格式的内容。新工作台在格式失败或外部请求状态未知时停止后续自动调用，保留原请求、用量及错误。旧版部分步骤支持最多 1 次格式修复，修复请求也占用预算。服务端仍校验输出格式、字段上限和当前事项关联，不保证每次分析成功。模式或接口不符时明确报错，不会自动切换为其他模型。

## 形成一份项目分析

1. 在首页输入一个想法，选择已配置模型，点击“开始分析”。工作台建立后再开始模型调用。
2. 在五个工作面板查看当前公开输出、已有结论和相关记录。单选题点选即保存；文字、数字和多选用“继续”提交，也可选择暂时不知道或跳过。
3. 保存成功后，短回执回到实际接收角色，并打开下一题。失败时保留输入，结果未知时先核对原请求。
4. 通过“补充”改变要求。受影响事项及其依赖重新核对，旧分析不再代表当前内容。
5. 最多回答 8 个关键问题，或提前生成分析。系统随后完成可行性、制作路径和报告整理，明确哪些条件尚未核实。
6. 阅读报告后，可复制、下载或直接“采用这份分析”。采用绑定当前报告，不把 AI 建议或未知事项变成已经确认的事实。

报告交付后停止自动提问。需要深入时，点击“再问 3 题”开启有限额的补充轮次。项目可能得到可行、有条件可行、不可行或信息不足的结论；这些都可以成为有用的分析。已有内容保存在 SQLite，刷新会恢复当前任务。当前调度由打开的页面触发，旧版后台 worker 不负责继续新工作台任务。

## 使用旧版推演与记录

在 `/?legacy=1` 使用以下既有流程；附件提取、三路线比赛与条件重赛仍属于旧版流程。

1. 填写目标并选择模型。当前提供 GPT 6.1 Terra、GPT 6.1 Sol、GPT 6 Astra、GPT 6 Luna 和 DeepSeek V4.1 Flash，默认 Terra；条件版本也支持按规则选择的自动模式。可上传附件，经补问和摘要确认后开始推演。预算、时间与备选方案可以选填。
2. 开始后查看独立提案、交叉质疑、证据核验、策略修订和条件裁决。
3. 点击质疑查看原话、工具证据和修订回应。也可以对具体判断提交自己的质疑。
4. 选择“修改条件再开局”，说明原因并提交新条件。版本选择器可以查看历史。

每个新版本保存有效模型配置及其 SHA-256 指纹。模型、接口、提示词、输出模式等配置变化时，旧版本停止后续步骤，避免混用配置；需要创建新版本继续。轮换 API 密钥不改变配置指纹，密钥本身也不进入记录。

材料支持 PDF、Word、表格、文本和图片。文档提取、模型图像转录与模型解释分别保留来源；模型生成的材料不能自行充当已核实事实。检索使用用户提供及确认的材料，未接入实时互联网搜索。计算工具保留表达式与假设，外部事实缺少依据时保持未知。附件限制、补问、恢复和快速复核见 [使用说明](docs/guided-input.md)。

快速复核由 GPT 6 Luna 的 Decisions 接口单独执行，协议为 `decisions-review-1.2.0`。它保留独立结果、用量和费用，属于模型检查，不能代替真人评价。所有费用均为依据用量计算的估算，以服务商账单为准。

预览服务可以要求访问口令。生产环境需要填写 `ARENA_ACCESS_CODE`；只有明确公开演示时，才设置 `ARENA_PUBLIC_DEMO=true`。

浏览器通过签名的 HttpOnly Cookie 持有访问身份。知道擂台编号不等于拥有访问权限。清除 Cookie、换浏览器或更换会话密钥后，原身份可能无法恢复；当前没有账号找回功能。

旧版默认由页面推进。长驻 Node.js 服务可以设置 `ARENA_WORKER_ENABLED=true`，让旧版已创建的任务在关闭页面后继续；该 worker 不推进新工作台。进程停止期间任务不会执行；外部请求状态不确定时会暂停，避免自动重复计费。serverless 环境不保证后台持续运行。

## 本地检查与自动检查

```sh
pnpm typecheck
pnpm lint
pnpm test
node --test scripts/*.test.mjs
node scripts/validate-evals.mjs
pnpm build
pnpm exec playwright install chromium webkit
pnpm test:e2e
```

GitHub Actions 使用冻结锁文件安装依赖，执行类型检查、代码检查、单元测试、构建和 Chromium 端到端测试。新工作台另用 WebKit 检查纸面交互、动画和窄屏流程。成功后打包独立运行文件，生成包含提交 SHA 和文件哈希的清单。失败追踪、截图和日志按提交 SHA 保存，保留 14 天。本机已有 Google Chrome 时，也可以用 `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e --project=chromium`。配置见 [CI 工作流](.github/workflows/ci.yml)。

端到端测试分为两种：真实 standalone 服务测试访问口令、缺钥错误和访问隔离；标有 `explicit UI fixture` 的测试使用合成响应检查页面流程。合成响应只存在于测试中，不能作为模型质量证据。CI 不配置真实模型密钥，不调用付费模型。

新工作台的真实模型验收使用独立入口，默认只展示计划，不读取私有环境文件、不打开数据库，也不调用模型：

```sh
node --import tsx scripts/live-planning-acceptance.ts
node --import tsx scripts/live-planning-acceptance.ts --case portfolio --model-mode gpt-6.1-terra
```

真实执行必须显式指定 `--run`、单个案例、模型和输出记录，并使用已有共享账本。运行器复用生产 planning 流程，检查五角色输出和提前生成分析；不自动代答、采用报告或开启补充轮次。它不能代替真人交互和语义质量验收。完整命令、边界与记录字段见 [新工作台真实验收](docs/planning-live-acceptance.md)。

旧版 `live-smoke`、`live-acceptance`、`live-guided-acceptance`、`public-acceptance` 及三组评测仍走旧版接口。真实三组运行器支持 `strong-single`、`independent` 和 `arena`，采用评测协议 `2.1.0`，并导出匿名评分卡。同一案例与方法的初始条件、变化条件共同受 1.5 元、600,000 Token 和 12 次工具请求上限约束；相同上限不代表相同实际消耗。12 个评测定义、运行命令和人工评分步骤见 [评测说明](docs/evaluation.md)。这些结果不能作为新工作台验收证据。

修复前的冻结留出运行已结束：24 条轨迹中完成 22 条，48 个条件输出中完成 46 个，费用估算合计 16.2759432 元。该记录对应配置 `1.2.0` 和提交 `1c7b4cd`，没有人工评分。当前 `1.2.1` 已修复约束状态优先级，工具哈希与旧评测不同；旧记录仅作历史协议诊断，不能作为当前候选的质量验证或方法胜出证据。

真实执行以共享账本的最新审计限额和剩余额度为准。DeepSeek 与 GPT 保留原币用量，所有工作区、网页和命令请求共用限额；历史授权不能直接作为当前可用余额。运行按案例、模型、配置和源码身份单独核对，旧结果不能代表当前 5 种模型均已验收。未知费用保留预留，不自动重试；新批次出现未知请求时停止。

历史 `266306c` 演示暴露了 C 路线继续计划 AI 镜头，以及“第 55 小时前”的可疑时间表述。原输出保留，不能把服务端状态修复当作模型语义已修好。`v0.2.0` 的同源真实演示已完成，两版均条件推荐 B；C 改为已有照片的风格化与转场，但是否保持事实仍需用户判断。该次运行没有再次出现时间表述问题，也没有覆盖原始 `violates` 分支；它不能证明这些问题已经消除。演示、PDF 与验收记录见 [预览 Release](https://github.com/songyu00yo/strategy-arena/releases/tag/v0.2.0)。

## 部署与提交

构建使用 Next.js standalone 输出。生产服务应只监听回环地址，由现有反向代理提供 HTTPS。不要把模型密钥、SQLite 数据和已有代理服务的私有文件装进发布包。

`pnpm build` 会绑定构建时的提交、源码指纹和编译产物。构建后再提交、修改源码或改变编译文件，都需要重新构建；打包器不会把旧构建标成当前提交。

[部署说明](docs/deployment.md) 给出版本目录、原子切换、回滚模板和发布清单命令。模板尚不能证明服务器已部署。只有真实 HTTPS 地址、健康检查、真实模型流程和隔离测试全部通过后，才能记录部署验收结果。

[范围与验收](docs/acceptance.md) 保留 P0 计划；[内部质量门槛](docs/quality-gate.md) 列出本轮冻结条件与竞赛来源核对。最终 `v1.0.0-provincial` 标签应在冻结提交和材料核对后创建。当前工具不会自动创建最终标签。
