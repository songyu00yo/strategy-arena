# 方案擂台

## 这个项目做什么

方案擂台让同一个模型从不同角色提出 3 条策略，再依次质疑、核验、修订和裁决。用户可以更改条件，保留旧版本后重新推演。应用面向学习、生活、工作和创作中的具体决策。

历史预览版本为 `0.2.0`，对应不可变的 `v0.2.0` 发布记录。当前开发版已实现目标补问、附件提取、5 种模型选择、条件重赛与快速复核；这些新增能力不属于历史预览的验收范围。截至 2026 年 11 月 7 日，本轮可靠性修复仍待完整验收，真人评测、公网验收和省赛封版尚未完成。代码测试、测试替身、真实模型运行与真人评价分别记录。

本轮以全国一等奖为努力目标，执行 [内部质量门槛](docs/quality-gate.md)。门槛用于决定是否可以冻结材料，不对应官方固定获奖分数线；奖项取决于正式评审，项目没有获奖或模型优越性承诺。

独立负责人为 `songyu00yo`，开发使用 Codex 等 AI 工具辅助。

## 本地启动

需要 Node.js `24.19.0` 和 pnpm `11.19.0`。数据库使用 Node.js 内置的 `node:sqlite`，请使用 Node.js 24。

```sh
npm install --global pnpm@11.19.0
pnpm install --frozen-lockfile
test -e .env.local || cp .env.example .env.local
```

已有 `.env.local` 时不要覆盖。用编辑器填写 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`、会话密钥，以及共享账本的绝对路径 `ARENA_BILLING_DATABASE_PATH`。配置说明见 [模型与费用](docs/model-budget.md)。该文保留早期预算记录；截至 2026 年 11 月 7 日，本轮累计上限为 10 美元、650 次请求和 5,000,000 Token，以共享账本审计值及匹配的环境设置为准。会话密钥可以在本机生成：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
pnpm dev
```

在浏览器打开 [本地应用](http://127.0.0.1:3000)。密钥只放在服务端环境文件中。填写后的 `.env.local` 已加入忽略规则；不要提交、截图或粘贴密钥。更改环境配置后重启服务。

DeepSeek 路径使用官方 Beta 接口 `https://api.deepseek.com/beta`，模型标识为 `deepseek-flash`，结构化输出模式为 `strict-tool`。DeepSeek 基础配置版本为 `1.2.1`；当前提示词版本为 `1.2.5`，Schema 版本为 `1.1.0`。模型别名可能由服务商更新，并不代表不可变模型快照。配置依据和价格估算见 [模型配置](config/model.json)。运行记录还应保留服务商实际返回的模型标识与用量。

缺少模型密钥时，页面会显示配置提示，阻止开始推演。API 创建空擂台后，推进接口会返回 `MODEL_NOT_CONFIGURED`；生产路径不会生成模拟回答。

真实模型可能返回不符合约定格式的内容。已知格式校验失败时，每个步骤最多增加 1 次格式修复请求；原始失败与用量会保留，修复请求也占用预算。超时等未知请求状态不会自动重试。默认以 strict 函数参数提交结果，并把本轮实际存在的主张、攻击和证据编号写入允许范围。服务端仍校验字段上限、原话和证据关联，不保证每场推演成功。模式或接口不符时明确报错，不会自动切换为 JSON 模式或其他模型。

## 完成一轮推演

1. 填写目标并选择模型。当前提供 GPT 6.1 Terra、GPT 6.1 Sol、GPT 6 Astra、GPT 6 Luna 和 DeepSeek V4.1 Flash，默认 Terra；条件版本也支持按规则选择的自动模式。可上传附件，经补问和摘要确认后开始推演。预算、时间与备选方案可以选填。
2. 开始后查看独立提案、交叉质疑、证据核验、策略修订和条件裁决。
3. 点击质疑查看原话、工具证据和修订回应。也可以对具体判断提交自己的质疑。
4. 选择“修改条件再开局”，说明原因并提交新条件。版本选择器可以查看历史。

每个新版本保存有效模型配置及其 SHA-256 指纹。模型、接口、提示词、输出模式等配置变化时，旧版本停止后续步骤，避免混用配置；需要创建新版本继续。轮换 API 密钥不改变配置指纹，密钥本身也不进入记录。

材料支持 PDF、Word、表格、文本和图片。文档提取、模型图像转录与模型解释分别保留来源；模型生成的材料不能自行充当已核实事实。检索使用用户提供及确认的材料，未接入实时互联网搜索。计算工具保留表达式与假设，外部事实缺少依据时保持未知。附件限制、补问、恢复和快速复核见 [使用说明](docs/guided-input.md)。

快速复核由 GPT 6 Luna 的 Decisions 接口单独执行，协议为 `decisions-review-1.2.0`。它保留独立结果、用量和费用，属于模型检查，不能代替真人评价。所有费用均为依据用量计算的估算，以服务商账单为准。

预览服务可以要求访问口令。生产环境需要填写 `ARENA_ACCESS_CODE`；只有明确公开演示时，才设置 `ARENA_PUBLIC_DEMO=true`。

浏览器通过签名的 HttpOnly Cookie 持有访问身份。知道擂台编号不等于拥有访问权限。清除 Cookie、换浏览器或更换会话密钥后，原身份可能无法恢复；当前没有账号找回功能。

本地默认由页面推进。长驻 Node.js 服务可以设置 `ARENA_WORKER_ENABLED=true`，让已经创建的任务在关闭页面后继续。进程停止期间任务不会执行；外部请求状态不确定时会暂停，避免自动重复计费。serverless 环境不保证后台持续运行。

## 本地检查与自动检查

```sh
pnpm typecheck
pnpm lint
pnpm test
node --test scripts/*.test.mjs
node scripts/validate-evals.mjs
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

GitHub Actions 使用冻结锁文件安装依赖，执行类型检查、代码检查、单元测试、构建和 Chromium 端到端测试。成功后打包独立运行文件，生成包含提交 SHA 和文件哈希的清单。失败追踪、截图和日志按提交 SHA 保存，保留 14 天。本机已有 Google Chrome 时，也可以用 `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e`；CI 仍使用固定依赖版本安装的 Chromium。配置见 [CI 工作流](.github/workflows/ci.yml)。

端到端测试分为两种：真实 standalone 服务测试访问口令、缺钥错误和访问隔离；标有 `explicit UI fixture` 的测试使用合成响应检查页面流程。合成响应只存在于测试中，不能作为模型质量证据。CI 不配置真实模型密钥，不调用付费模型。

真实模型验收需要单独执行，并记录输入、条件变化、证据、用量和失败情况。真实三组运行器支持 `strong-single`、`independent` 和 `arena`，采用评测协议 `2.1.0`，并导出匿名评分卡。同一案例与方法的初始条件、变化条件共同受 1.5 元、600,000 Token 和 12 次工具请求上限约束；相同上限不代表相同实际消耗。12 个评测定义、运行命令和人工评分步骤见 [评测说明](docs/evaluation.md)。

修复前的冻结留出运行已结束：24 条轨迹中完成 22 条，48 个条件输出中完成 46 个，费用估算合计 16.2759432 元。该记录对应配置 `1.2.0` 和提交 `1c7b4cd`，没有人工评分。当前 `1.2.1` 已修复约束状态优先级，工具哈希与旧评测不同；旧记录仅作历史协议诊断，不能作为当前候选的质量验证或方法胜出证据。

后续总授权为 200 美元，本轮累计限额为 10 美元、650 次请求和 5,000,000 Token。DeepSeek 与 GPT 保留原币用量，所有工作区、网页和命令请求共用限额；历史人民币安排和初次 2 美元上限仅作历史记录。真实运行按案例、模型、配置和源码身份单独核对，旧结果不能代表当前 5 种模型均已验收。未知费用保留预留，不自动重试；新批次出现未知请求时停止。

历史 `266306c` 演示暴露了 C 路线继续计划 AI 镜头，以及“第 55 小时前”的可疑时间表述。原输出保留，不能把服务端状态修复当作模型语义已修好。`v0.2.0` 的同源真实演示已完成，两版均条件推荐 B；C 改为已有照片的风格化与转场，但是否保持事实仍需用户判断。该次运行没有再次出现时间表述问题，也没有覆盖原始 `violates` 分支；它不能证明这些问题已经消除。演示、PDF 与验收记录见 [预览 Release](https://github.com/songyu00yo/strategy-arena/releases/tag/v0.2.0)。

## 部署与提交

构建使用 Next.js standalone 输出。生产服务应只监听回环地址，由现有反向代理提供 HTTPS。不要把模型密钥、SQLite 数据和已有代理服务的私有文件装进发布包。

`pnpm build` 会绑定构建时的提交、源码指纹和编译产物。构建后再提交、修改源码或改变编译文件，都需要重新构建；打包器不会把旧构建标成当前提交。

[部署说明](docs/deployment.md) 给出版本目录、原子切换、回滚模板和发布清单命令。模板尚不能证明服务器已部署。只有真实 HTTPS 地址、健康检查、真实模型流程和隔离测试全部通过后，才能记录部署验收结果。

[范围与验收](docs/acceptance.md) 保留 P0 计划；[内部质量门槛](docs/quality-gate.md) 列出本轮冻结条件与竞赛来源核对。最终 `v1.0.0-provincial` 标签应在冻结提交和材料核对后创建。当前工具不会自动创建最终标签。
